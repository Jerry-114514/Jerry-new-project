# 固定 k 开发实验的 GPU 干扰排查

2026-10-23。原450条开发记录已完成、远端退出0，完整归档已下载本地并核对SHA256，450条工具轨迹和指标已本地复算。完成状态与复算一致不等于对照实验有效。

## 已证实的原因

1. k=1的第36–122条（从1计数）连续87条，history记录同一错误：`Other CUDA compute processes are active (PIDs 175499)`。GPU租约发现另一个CUDA进程，拒绝继续装载或生成；87条交互时间合计约29.74秒，只有2次已发生的计费调用、3816 tokens。多数条目尚未实际调用模型。不是87次模型完成推理后作答错误，也没有OOM报错证据。
2. `run_task`将`GpuBusy`作为普通`RuntimeError`捕获，只保存message并返回error行；开发执行器仍继续后续任务。
3. 选择器将这些error行按不合规成功计入同一分母，仍生成completed报告和k=3排名。形式/哈希/回放检查验证的是文件与指标一致，没有检查资源事故是否使各组比较失效。

k=1共90条error，其中87条资源拒绝、3条JSON动作解析失败。k=2/k=3各8条error，均为模型输出解析/缺少actions错误。资源拒绝集中于k=1，因而该次17.33%/38%/38%的开发成功率不能作为公平的k效果比较；算法按原规则给出的k=3选择暂不可采用。原始失败不删除，不从分母选择性剔除后继续宣称实验有效。

## 尚不能确定的来源

PID175499现在已经结束。对本项目远端8809份小型JSON元数据查找PID/child_pid等字段，没有找到其所属启动记录。原GPU探测只保留PID，没有保存当时的父进程、命令、启动时间或PID命名空间映射。因此当前无法可靠区分独立作业、同一作业的子进程，或容器/主机PID映射问题；也不能认定来自某一项CPU检查。约30秒的连续拒绝支持短时资源事故，但不能据此反推具体程序。

## 修复范围与现状

本地修复增加错误类型记录；开发与冻结闭环在写入、flush保留事故行后立即失败，停止后续任务。选择器同时拒绝新结构化GpuBusy及已知旧版message-only资源错误，防止旧报告重新计算哈希后被正式绑定。普通模型JSON错误与明确token/上下文预算耗尽仍保留为模型/预算结果，不借资源事故处理删除它们。

本地282项检查含16项可选ML跳过，其余通过；独立服务器CPU环境全部282项通过、无跳过，测试日志140.449秒，驱动总计142.038秒。新增检查实际注入GpuBusy，验证第一条事故行和失败manifest保留、不生成选择、不开始k=2。旧450条轨迹与指标再次全部复算一致，同时新选择器明确拒绝旧报告用于选择；一致性与对照有效性分别记录。

本版另增加可选私有诊断日志：冲突发生时保存观察者与被报告进程的PID、父PID、启动tick、可见的命名空间PID及模块/脚本名称，不保存完整命令参数或环境变量；记录失败也不会放行GPU调用。见[原始检查、事故复算与重跑计划](../examples/results/formal-m3aa-gpu-interference/README.md)。

补救采用同样150个开发源、原顺序k=1/2/3、相同原始模型与全部预算，单独新建完整450条运行，不局部补87条、不混合旧新结果、不按结果修改阈值或数据。发布本版后从固定干净commit启动，启动前确认GPU空闲和预算守护在线，运行中保留进程遥测，任何新的资源事故均终止本次运行，不自动重试。模型JSON与明确token/上下文失败仍保留在分母。规划约4–6小时，不保证时长；费用计入原有私有预算上限，不能增加总预算。原450条完整保留，正式训练0/6。

独立的9B共享底座核验已退出0：两开发任务、两模式各6次调用，原始tokens/输出、除时间外的账本和资产前后SHA均一致。总耗时69.35秒对38.40秒、加载6次对1次，只描述这一小型工程核验，不能外推整个正式实验。该结果不能修复此前固定k比较的资源混杂。
