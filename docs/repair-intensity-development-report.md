# 修复数量 k 开发验证报告

日期：2026-10-22。这是 M1 工程和 M7 消融准备，不是确认性结果。人工审核仍为 0，正式协议未冻结，六次 9B 正式训练尚未开始。

## 结果及含义

新增 `fixed-k` 和 `dynamic-k`，用显式公开判断选择修复根数量，两组共享排序、依赖扩展、预算与门控。具体定义和命令见 [指南](repair-intensity-guide.md)。原有 `dynamic` 不改名、不重写结果。

| 开发检查 | 固定 k=1 | 固定 k=2 | 固定 k=3 | 动态 k |
| --- | ---: | ---: | ---: | ---: |
| 真实官方原始 9B：合规成功任务 | 2/8 | 未运行 | 未运行 | 2/8 |
| 受控规则执行器：注入数据和报告缺失 | 0/8 | 8/8 | 8/8 | 8/8 |

真实模型两组共 16 次运行，使用已有同一批 8 个公开开发源任务。每组 11 次执行调用、8 次分析调用，计费 20,645 tokens（prompt 17,325，completion 3,320），失败预留与预算拒绝均为 0。没有任何修复提议，所以 k 控制实际触发 **0/16**；不能据此声称动态控制有效或无效，也没有必要把其他固定 k 重复运行成同样的零机会样本。

成功的是金额舍入和半开区间任务；其余仍受执行停止或诊断误判影响。两组没有实际硬违规事件，也没有硬检查拒绝机会。严格原生执行包合规均为 0/11；11 次响应均有顶层额外回显字段，在共同的 extract 规则下提取原有 actions/done，未修改动作或自报完成状态。严格格式与可执行动作效果分开记录。

真实模型 mean elapsed 分别约 13.54 与 12.09 秒/任务，存在初次加载和顺序差异，不解释为动态 k 加速。两组相同的 token 数及零次控制器触发更直接地表明，此次没有观察到动态预算收益。

受控规则执行器在初始阶段只做必需字段校验，故意遗漏全部交付物。固定 k=1 按公共 ID 顺序首先选中报告，而报告不能单独补全数据，因此连续三轮未通过门控。动态 k 选中两个根要求并联合修复；但固定 k=2、3 同样一次修复成功，调用数与动态 k 相同。这证明目标选择和审计接口能工作，也说明单独击败固定 k=1 不能证明动态性的价值。

受控检查分别运行三个固定 k 配置，每个配置附带同映射的动态组，共 48 条工具轨迹。动态组是重复对照，不是新增独立样本。与真实模型合计 64 条原始记录，独立来源仍只有声明的 8 个开发源任务，不能当作 64 个独立测试任务。受控运行没有模型 token，不能用其调用数推断 LLM 计算公平或成本收益。

## 环境、记录与核验

真实执行器和分析器均为官方 Qwen3.5-9B 原始权重，无旧适配器；revision 为 `c202236235762e1c871ad0ccb60c8ee5ba337b9a`。单张 RTX 5090，本地 BF16 贪心推理，上下文上限 4096、单次生成上限 512、每任务共享 token 限额 16,384、最多三次修复、每份提议最多三步工具反馈和累计 16 个动作。独立硬检查开启，历史可见。

13 项官方权重/tokenizer 资产已再次核验。实际交互源代码在运行后保存指纹，36 个 `intentlab` 模块与最终上传版本一致；这不是预先正式冻结。最终新增硬检查回归测试与汇总脚本在推理后补充，不影响已经执行的模型交互。最初远端 104 项测试通过，最终完整 105 项测试也全部通过；本地 105 项中 98 项通过，7 项因无 ML 依赖跳过。

全部 64 条轨迹通过独立工具重放、离线指标与新增违规归因核验，64 个受控 k 决策可从提议前在线判断重新计算；真实模型没有决策可重算。已加入篡改 k/配置拒绝、阈值边界、unknown、依赖扩展、公共同步补证、强固定 k 以及独立硬检查不被控制器绕过等测试。

发布目录：[原始结果与核验](../examples/results/formal-m1e-intensity/README.md)。可从仓库根目录运行：

```bash
python scripts/summarize_intensity_development.py
```

脚本重算四个目录的工具效果、指标、决策和预算，对照已保存汇总，核对随包保存的 36 模块交互源码，再生成 `verification.json` 与逐文件 `checksums.json`。后续分析器修复不覆盖该源码快照；当前离线审计器重算相同工具合同。也可用 `--source-root` 核验该交互实现的另一份完全相同副本。公开文本统一使用 LF；此行尾规范化不改变 JSON 字段和原始模型输出中的转义字符。

开发失败也保留说明：首版受控报告包装器漏填 `actor`，16 条受控工具轨迹已经生成，但报告生成报 KeyError；补齐元数据后在新目录重跑成功，发布的是修正后的完整运行。该包装器失败不作为模型或控制器质量样本。

## 正式实验尚需补齐

首要改进方向是诊断可靠性和修复机会覆盖，不能继续仅调 k 期待解决错误的 satisfied 判断。正式方案需要独立新任务、真实双人标注、强提示与规则基线、冻结的适配器选择、固定 k=1/2/3 开发比较及全部计算预算，再做隔离测试和任务级统计。执行条件与数据仍需接入冻结协议及测试揭晓审计。

本轮没有完成正式 M3–M8，也没有验证学习率反馈、风险反馈学习率或新算法优势。正式目标与负结果保留，后续不能把本批公开开发任务放入确认性测试集。
