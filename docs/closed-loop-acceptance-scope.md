# 闭环接受规则与独立硬检查的解释边界

2026-10-27。此说明核对已冻结的代码和已公布的M6汇总，不增加实验条件、不重新评分、不读取M7逐例结果，也不改变运行中的模型、控制器或统计方案。局部`intentlab/`与冻结提交20214fb没有差异。

## 四条件实际比较什么

|机制|P1/P2|P3/P4|
|---|---|---|
|真实模型提出修复候选|有|有|
|模型分析候选后的要求状态|有|有|
|共同接受规则`gate`|有|有|
|独立规则硬检查`repair_hard_guard`|关闭|开启|
|最终静态参考评分|全部交互封存后|全部交互封存后|

[冻结配置](../examples/results/formal-m3af-protocol-freeze/freeze-receipt.json)的`analyzer_mode`为`model`，分析器是按验证集绑定的D条件seed 0。没有在正式执行中临时切换到规则或hybrid。代码支持hybrid并不代表本轮使用它。

[冻结runner](https://github.com/Jerry-114514/Jerry-new-project/blob/20214fb28ba1c8a4a2be0be075c97e33eedb2ba0/intentlab/runner.py)的顺序是：克隆当前状态、生成完整修复候选、执行可选独立硬检查、调用分析器判断候选、满足接受规则后才提交候选。即使独立硬检查拒绝，候选分析调用仍会发生；不能从“先拒绝”推论已经节省了该调用或token。

[共同接受规则](https://github.com/Jerry-114514/Jerry-new-project/blob/20214fb28ba1c8a4a2be0be075c97e33eedb2ba0/intentlab/analysis.py)根据分析器报告拒绝：原已满足要求的退化、新出现的已知硬违规、未能确认的硬约束，以及没有任何原违规变为满足的候选。该规则在P1–P4中一直存在。因而RQ2的实际估计对象是：**在共同的模型驱动接受规则之上，增加独立硬检查的增量效果**。P1/P2不是任意候选直接提交的条件。

[独立硬检查](https://github.com/Jerry-114514/Jerry-new-project/blob/20214fb28ba1c8a4a2be0be075c97e33eedb2ba0/intentlab/hard_guard.py)使用公开规则、可信事件和文件快照，检查候选历史前缀、输入写删及快照变化、验证与写入顺序；不依赖模型是否报告违规。正式mode为model，因此共同接受规则可能受模型漏判影响，不能把两个检查机制视为对所有可能候选逻辑等价。如果模型错误地报告没有硬退化并报告了其他改善，共同规则可能接受真实不安全候选，而独立检查仍可能拒绝其已编码违规；这是代码层面的条件推论，本轮没有据此新增成功案例或宣称实测收益。

## 本轮实际观察

以下数字直接来自已公布的[M6 summary.json](../examples/results/formal-m6c-execution-results/summary.json)，只解释已登记的描述性结果：

|每条件的候选类别|P1/P2各自|P3/P4各自|
|---|---:|---:|
|不完整或提案错误|19|19|
|完整候选因`no_verified_improvement`拒绝|7：test 1、OOD 6|0|
|完整候选因`protected_requirement_regressed`拒绝|2：均test|2：均test|
|完整候选因`hard_guard_validation_order`拒绝|0|7：test 1、OOD 6|
|接受的修复|0|0|

四条件均28次修复尝试、9个完整候选；没有完整且合规的候选。拒绝理由的分布不同，但最终均未提交修复，逐任务最终文件及事件状态相同。汇总计数本身不证明跨条件每个候选完全相同，也不能据此给每次拒绝作因果归因。误拦截率的合规候选分母为0，仍报告null。

因此，七次独立检查拒绝说明该机制确实执行过，但不能单靠这个计数证明减少了最终已提交违规。本轮没有观察到其增量安全收益；共同接受规则和有限候选机会限制了这一比较的解释。该结论不等于证明独立硬检查无效，也不支持无检查系统安全。

## 保护范围

独立硬检查开关作用于修复候选。初始提案直接在初始状态上执行，随后才分析；本轮没有用该开关保护初始执行。原有不可逆违规和修复新增违规必须继续分开报告，不能把P3/P4描述成整条轨迹始终受独立检查保护。M6中test 4个、OOD 7个初始不可逆违规仍保留在全部任务结果中，初始可行分层另报。

这些是现有实现、设计和已封存负结果的解释边界，不是额外确认性检验。18项预登记比较、全部样本、失败记录和正式统计方法保持不变；任何不同接受规则或新的执行保护设计需要另行登记与验证，不能用重跑当前测试来改善本轮结果。
