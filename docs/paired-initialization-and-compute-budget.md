# 初始化证据与完整模型阶段的预算草案

2026-10-23。idea.md要求两调度各三个种子采用相同实际初始化与数据顺序。原矩阵核对seed、数据、基础模型、监督量和样本暴露，但未记录初始适配器张量。新增训练前的trainable tensor SHA256（含参数名、dtype、shape及字节），写入每次checkpoint和result；恢复时对照重新构建的初始张量，错误指纹直接拒绝。旧checkpoint没有该观察值时继续标null，不能用重新生成的初始化补造历史证据。正式矩阵与端点绑定现要求有效指纹并核对同seed两调度相同；旧工程结果仍可复算而不宣称初始化已核验。

此修改不改变损失、学习率、抽样或参数更新，未部署至运行中的d80be96。两个轻量检查验证实际结果绑定、缺失/不一致/非法指纹拒绝和旧工程保留；本地完整267项测试中15项可选ML检查跳过，其余通过。后续AutoDL独立CPU检出c8eb676的三个相关套件共19项已全部通过，其中实际tiny LoRA检查覆盖同seed两调度、不同seed、篡改恢复拒绝及旧checkpoint保留unknown。证据见[M3v](initialization-evidence-preparation.md)，不将本地跳过称为通过或将CPU证据称为任意CUDA等价证明。

## 全阶段计算量与成本

| 阶段 | 固定工作量 | 规划GPU时长 |
| --- | --- | --- |
| M4 | 2464更新×6模型；每模型两epoch、4928次样本暴露、769088监督tokens；13次完整验证 | 约22–40小时 |
| M5 | 1240 heldout视图×8语言模型条件，共9920次生成；规则C另算，六模型损失另算 | 约20–35小时 |
| M6 | 300 heldout源×P1–P4，共1200次闭环 | 与M7合计约55–110小时 |
| M7 | 300源×三个固定k、dynamic-k及两种移除权重消融，共1800次闭环 | 同上 |

合计粗约100–190 GPU小时（约4–8天串行计算）；不包含当前450次开发选择、CPU构建、人工阅读、故障修复和长期备份，不是保证完成时间。四组闭环和消融为真实模型任务，不能用微型工程测试或训练步数代替。

训练估算分别参考原全量632视图验证约321秒、平均训练长度比例，以及最长9086训练/12150验证的两步压力总循环51.35秒；对新增长历史及非线性长度成本保留宽区间，尚无完整2464更新吞吐实测。新验证总长度比原增加约9.9%，每模型13次验证需单独计入，不直接用两个压力样本的wall当全量训练成本。

M5按旧完整600视图的A/B3条件墙钟4077.54/5668.24秒作代理，微调端点实际吞吐未知。M6/M7沿用当前实现：每个任务冷启动、actor和adapter-analyzer轮换时至多常驻一个模型，完整计模型加载成本。既有自然采集首个原模型加载约9.68秒；若3000次闭环每任务均执行初始actor与analyzer两次角色加载，仅这些加载就约16小时量级；初始失败可能跳过后续角色，修复轮换则可能增加开销。原始同路径双角色开发选择的吞吐不能直接当作正式闭环速度。

闭环每任务49152共享token上限，M6+M7累计最多147456000计费tokens；开发选择另有22118400上界。上界是token账本的硬限制，**不是GPU时长或费用上界**。达到上下文、token、工具步或修复上限的记录全部保留，不能只报成功任务的成本。
