# 压缩提示的开发对照计划

日期：2026-10-23。该计划只检验两种序列化方式的接口、引用和预测分歧，供 M3 开发决策使用，不是正式研究协议、质量验收或微调实验。

执行状态：208次计划调用已全部完成，原始结果和负结果均保留；实际结果见[开发报告](compact-prompt-development-report.md)。以下保持原计划的范围、预算及指标，不能把完成调用当作人工效果验证。

104 个开发视图来自已经固定的三个批次，数据内容和顺序与 [M3c 长度审计](context-coverage-budget.md)相同。它们包含 train/validation，来源独立性及人工状态真值尚未核验；所有 view 均保留，不按运行表现选择子集。

每视图各执行一次完整提示与压缩提示，计划208次调用；偶数索引先完整后压缩，奇数索引先压缩后完整，各52对。单个官方原始 Qwen3.5-9B 常驻GPU，非思考模板、贪心生成。每次重置共享账本，固定上下文6144、最大输出512、硬预算8192 tokens，无重试。6144 足以容纳已测最长完整提示4691及512输出预留，避免以不同上下文上限比较两种格式。该推理配置不代表6144长度训练可行。

压缩条件保持完整 public、输出 Schema 和全部合法引用键，仅去除目录中重复的值，并提供明确查找规则。默认核心提示不变；本次通过独立驱动显式构建两种字符串，逐调用记录真实prompt哈希、预算、时间和原始输出。两种格式不共享对话或上一条输出，未传入参考、标签、oracle、规则诊断或少样本答案。

分析预先固定为：

- 严格 Schema 解析和既有 ID 对象归一化分别报告；不去除 Markdown 围栏、不依据结果增加修复规则。
- 引用必须存在，satisfied/violated 须非空；这不证明证据语义支持结论。
- 按双侧均可解析的逐要求预测计算状态和引用集合分歧，另报不可比较视图/要求数，保证分母完整；分歧不是相对人工真值的错误。
- 报告预分词prompt数、实际已知生成tokens、含失败预留的计费tokens和生成阶段时间。加载及预处理开销另存，不将生成时间当整个工作耗时。
- 所有生成失败和解析失败保留；无法确认实际生成长度的错误按既有账本保守计费。

原始模型响应和私有案例留在协调人目录，仓库仅发布聚合结果、哈希及重算程序。运行记录必须达到208次、固定模型资产再核验完成后才能声明本轮完成。分析器已增加合成检查，验证缺失/重复调用拒绝、围栏失败保留、错误引用与状态分歧分开、失败预留计费；这些检查不提供人工标签或模型效果证据。

即使压缩接口通过率更高，也不能直接认定诊断更准确。后续仍须实际双人标注、少样本B、审核后的SFT目标长度和正式冻结；是否采用压缩格式应对正式各条件统一版本化，并保存旧开发结果。
