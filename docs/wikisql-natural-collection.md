# WikiSQL 来源开发合同的自然执行采集

本批延续 [12 份显式合同适配](wikisql-equality-adaptation.md)，推进 M2 的自然错误收集及人工审核准备。所有任务属于 train 开发用途，来源保真、授权、语义独立性及人工标签均未审核；没有建立新的正式测试集。

## 采集设计

前两题已有真实执行记录，保持原样，不重复抽样；剩余十题按既定适配顺序各执行一次。固定官方 Qwen3.5-9B 原始权重，CUDA、本地共享 token 账本，每题 8192 tokens、单次最大生成 768 tokens、上下文 4096，最多三次工具步骤。策略为 none、修复次数为 0；公开规则分析器作开发诊断，离线参考只用于交互结束后的候选评分。

这里的“初始执行”可能包含工具反馈后的继续调用，不等于一题只调用一次。采用既有 extract 格式投影，必须同时报告原始严格接口及投影计数。它不是学习后的分析器或修复条件比较，也不复现原 WikiSQL 自然语言转 SQL。

两批分别保存完整 manifest、模型原始生成、提示哈希、工具事件、账本、程序异常、最终文件及候选指标；不改写前两题、不删除未完成题。合并只用于描述这 12 个既定合同，不能根据结果选择进入合并集的题目。

## 盲包和审核工作量

每次真实执行生成完整事件与仅快照两个视图，共 24 个。两视图共享同一源任务；本批与 48 个注入视图也共享来源，不增加独立合同数。12 份合同只有一个共同项目模板，不能据此声称跨领域泛化。

每位审核者提交 24 条案例记录、96 项逐要求判断；两人合计 48 条、192 项判断。有分歧时由不同于初审两人的第三人仲裁。包仅包含公开请求、输入、规格、观察和空白模板，没有 oracle、模型原文、指标、方法身份或诊断标签。协调人的轨迹映射不发给初审人员。

本地准备包路径：`runs/annotation-reviewers-wikisql-natural-20261023.zip`。批次指南随包提供，通用规则见 [人工标注流程](human-annotation-workflow.md)。包准备好不代表已分发，当前人工审核为 0；分发前仍须完成来源与要求核对。

## 结果与复现入口

完整计数以 [M2e 证据目录](../examples/results/formal-m2e-wikisql-natural/README.md)的 `collection-summary.json` 和 `execution-summary.json` 为准。候选参考合规率不是人工准确率，程序异常为 0 也不意味着所有任务完成。

2026-10-23 实测：12 题中候选参考合规 7 题、未合规 5 题，硬约束违规运行 2 次。共 21 次调用、40,461 个计费 tokens；原始严格接口通过 0/21，19 次成功解析调用经过既有投影，另两次分别因工具动作 Schema 和 JSON 解析不合法而记录 error。这是被 runner 捕获并保留的模型接口失败，采集进程正常结束，不是两次进程崩溃。所有 12 题均计入分母，未重试坏输出或删除失败；逐调用回放已经核验。

默认审计只验证公开元数据。提供固定来源归档后重建同一 600 条来源池与 12 份合同；另提供私有记录时，重建每次提示，按原始响应回放解析、工具、诊断和离线指标，再重建两个标注批次及合并盲包，不重新推理。

```bash
python examples/results/formal-m2e-wikisql-natural/audit.py
python examples/results/formal-m2e-wikisql-natural/audit.py --archive /private/data.tar.bz2 --private-root /private/wikisql-natural
```

原始问题、表格、合同、参考、模型生成和盲包继续私有保存。仓库发布代码、指纹、计数及可复核的审计入口。此进展不能替代正式 M2 双审、M3 冻结、M4 六组训练或 M6 四条件闭环。
