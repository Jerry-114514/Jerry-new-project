## 当前已实现的范围

本项目提供纯 Python、无需 GPU 或第三方依赖的最小研究工具：虚拟文件环境、真实工具事件、公开要求的规则分析、独立交付评估、隔离候选修复、固定及动态纠偏、结构化评分、轨迹导出、平台学习率控制和轻量分类训练。

补充实现：已加入可选的真实因果语言模型训练、LoRA、检查点恢复、本地模型执行/分析、来源区间抽取和依赖组修复。安装与实测边界见[神经语言模型指南](neural-training.md)。

它落实了前序指南的核心流程，但没有宣称已经实现全部研究方案。没有开展 3B/7B QLoRA、LODE、Scaling Law 拟合或真实 LLM 成效比较；也没有将两个分开的阶段包装成新的联合控制算法。

## 一键顺序复现

Python 3.11 或更新版本，在仓库根目录执行；Windows PowerShell 和 Linux 均可使用：

```bash
python -m unittest discover -s tests -v
python -m intentlab build-data --out runs/data
python -m intentlab run --out runs/complete --repeats 2
python -m intentlab run --out runs/redacted --repeats 2 --redact-events
python -m intentlab train-baseline --data runs/data/diagnostic_views.jsonl --out runs/training
python -m intentlab replay --records runs/data/trajectories.jsonl
python -m intentlab replay --records runs/complete/runs.jsonl
```

`runs/` 默认不进入版本控制。仓库内 `examples/results/` 保存本轮实际运行结果，便于核对复现；训练样本和轨迹说明见 [数据说明](../data/README.md)。

`replay` 逐项重新执行已提交工具事件，核对事件哈希、最终文件和评估结果；不会仅仅信任记录中声称的工具结果。被拒绝候选仍在运行日志供审查，但不会作为已提交轨迹重放。

## 环境和执行语义

所有数据动作只发生在内存中的虚拟文件字典，不会执行模型返回的 Python、shell 或本机文件操作。路径必须是规范的相对 POSIX 路径，禁止绝对路径、盘符、反斜杠与 `..`。一份动作提议先进行完整格式验证，再应用。

`validate` 是工具检查：环境根据当前输入和任务定义计算字段是否齐全，不采信执行器自报的 `ok`。工具记录保留自报值和实际值。

候选修复在克隆状态中执行，只有通过要求保持检查且至少修好一个已确认违规项时才提交。被拒绝的候选记录在运行历史中，但不会污染正式执行状态。此性质仅适用于这个隔离的虚拟环境；不代表任意外部副作用可撤销。

检查区分当前状态与历史行为。即使先覆盖再恢复输入，输入保护要求仍然违反。最终输入相等不是全程未写入的证明。初始执行不受候选修复门控保护，因此系统不会通过隐藏已经发生的违规获得高分。

## 模块

| 模块 | 职责 |
| --- | --- |
| `core.py` | 状态、实际工具事件、路径约束、公开任务视图 |
| `actors.py` | 脚本化测试执行器，以及 HTTP JSON 执行器接口 |
| `analysis.py` | 规则分析、满足/违反/未知状态、多维评分和修复接受判断 |
| `oracle.py` | 仅最终评估读取的静态参考交付物及历史检查 |
| `runner.py` | 有界执行—分析—候选修复—复检—提交闭环 |
| `fixtures.py` | 虚构任务、受控轨迹和证据视图导出 |
| `schedules.py` | 预热余弦与平台触发调度器、可序列化调度状态 |
| `learning.py` | 真正进行梯度更新的轻量逻辑回归管线基线 |
| `report.py` | 原始记录、汇总、运行指纹和 Markdown 报告 |

在线规则分析器依据公开结构化规格重建要求；已实现本项目模板语法的原文区间抽取，遇到不支持的语法报错，尚不支持任意自然语言要求抽取。当前规则分析器不能发现规格与原文之间的所有偏差。正式研究须增加该环节的独立标注与诊断。

## 固定和动态纠偏

`none` 只运行初始提议；`fixed` 按固定要求顺序选择修复目标；`dynamic` 优先已确认硬约束风险，在日志缺失时主动读取权威日志补充证据。固定与动态都使用相同候选门控，避免故意削弱固定对照。

动态版本实现补证、目标选择，并在局部候选被拒绝后按显式依赖图扩展到组修复。例如数据结果变化可能影响报告行数。`fixed-full` 作为总是修复数据与报告的强对照；所有策略保留相同接受规则和全量复检。该图尚非学习得到。脚本化初始故障和修复退化由固定规则注入；不会因控制器名称改变执行器的求解能力。在完整证据下，两个策略可能获得完全相同结果，这属于合法输出，不能为制造优势修改数据。

每任务默认最多 3 次修复和 1 次有效日志补充。记录模型/执行器调用、检查、提议动作和拒绝次数。此版本尚未强制真实提供商的总 token 预算，不能把调用上限相同当作 token 或延迟公平。

运行记录中的 `elapsed_seconds` 覆盖单个任务的执行、分析、修复与最终评价，不包含实验开始时的模型加载。汇总同时报告有计时数据的运行数；旧日志没有计时值时不补零。时间是本机观测值，不要求重放时相等，也不是目标显卡吞吐基准。

## 轻量训练

`train-baseline` 用 9 个可观察的规则特征训练二分类逻辑回归，标签来自独立评估：该要求是否违反。特征为输入变化、顺序异常、数据异常、报告异常、历史缺失与要求类型 one-hot。

这是用于验证损失、学习率事件、种子与检查点选择的简单管线基线。规则特征已经包含强诊断信号，分类准确率不能证明模型学会理解用户要求。分类器默认用于离线诊断，可通过 `--risk-model` 选择其权重对已确认违规项排序；不会覆盖硬约束判定或跳过复检。

比较 `cosine` 和 `plateau`，分别使用 3 个种子，共 6 次真实 CPU 训练。两组训练量相同，最多 24 个 epoch；仅验证集选择最佳权重，测试集在选定后评价一次。线性模型的学习率尺度与 QLoRA 不同，不可照搬其数值。

当前保存最佳分类权重、全程损失、最终调度状态；不提供完整训练恢复命令。最佳权重与最终调度状态未必对应同一步，因此不能将这份输出当作可直接续训的完整检查点。调度器本身的序列化恢复行为有测试。

本轮轻量数据上的验证损失持续改善，平台调度没有触发降低，结果文件记录 `lr_reductions=0`。因此不能将两种训练曲线的差异解释成“平台触发机制有效”；耐心窗口、冷却与下界由受控测试单独覆盖。

## 接入真实模型

HTTP adapter 使用项目自定义的 JSON 协议；它不是现成模型提供商的聊天端点。需要模型服务或桥接服务按以下格式提供 `/propose`：

```bash
python -m intentlab run --actor-url http://127.0.0.1:8080/propose --split test --repeats 1 --out runs/model
```

请求结构：

```json
{
  "task": {"request": "...", "spec": {}, "inputs": {}},
  "state": {"files": {}, "events": []},
  "phase": "initial",
  "target": null,
  "attempt": 0
}
```

实际 task 还含任务 ID、操作族和输出路径，但不含 `oracle`。响应例如：

```json
{
  "actions": [
    {"op": "validate", "ok": true},
    {"op": "write", "path": "output/data.json", "value": []}
  ],
  "claim": "completed",
  "usage": null
}
```

`claim` 不作为合规证据。仅允许 `validate`、`write`、`delete` 三类动作，每份提议最多 16 个动作，HTTP 响应最多 1 MB，单次请求默认超时 60 秒。模型返回任意命令不会被执行。当前不记录提供商 token 用量，也未提供鉴权或提供商 SDK；正式远程模型接入需补充服务身份和成本记录。

只有显式传入 `--actor-url` 时才发送任务内容。默认脚本化实验完全离线。HTTP 适配器已用受控假响应测试请求格式、参考答案隔离和超限处理，未连接真实模型服务。

## 已运行结果的解释

实际硬件检测为 RTX 5070 Laptop GPU，约 12GB 显存；本轮核心、轻量训练和新增微型神经模型训练均使用 CPU，不需要该显卡。没有下载大型模型，也没有运行此前讨论的 5090 QLoRA 训练。

补充版本默认包含 none、fixed、fixed-full、dynamic 四种策略。每个证据设置有 40 任务 × 4 策略 × 2 重复 = 320 次脚本化运行，两种证据设置合计 640 次。脚本重复是相同执行，不是独立随机样本。

在完整证据演示中，固定和动态策略结果相同；隐藏历史时，动态策略进行了额外日志补证。初始输入写入风险仍保留为最终违规，没有被恢复或任务完成抵消。详细数值以 [完整证据报告](../examples/results/complete-evidence/REPORT.md)、[隐藏历史报告](../examples/results/redacted-evidence/REPORT.md) 和训练 JSON 为准。

本轮不提供显著性检验或方法优越性结论。数据、脚本化故障和简单特征都过于受控，只说明工具链可以端到端执行。
