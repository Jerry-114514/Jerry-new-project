# 规格内引用支持的补充评估

这是冻结主实验之外的补充、探索性评估。原始指南要求评测证据支持；现有正式评分只检查引用是否存在及非空，不能据此宣称引用支持判断。新评估不改动既有预测、标签、解析规则、模型、控制器或18项预登记比较，不新增确认性p值。

## 评估对象与背景

`scripts/evidence_support.py`的`EvidenceContext`只支持已有明确编码的四项规则：保护输入、写入前验证、输出精确匹配、报告计数。先验证任务/案例/参考绑定，并重放完整可见历史以拒绝伪造的工具结果。它不调用语言模型、在线分析器、执行评分器或程序状态标签器来判定引用支持。

背景事实明确包括公开合同、原始输入、输出/报告角色路径、可信虚拟工具语义，以及历史是否可见和事件数量。当前观察的文件值和事件内容必须被引用；引用完整历史时，可以从原始输入重放得到最终文件。`snapshot_paths`只提供完整路径清单，不自动提供所有文件值。该背景约定是指标的一部分，不能把结果描述为只凭孤立引用文本、脱离背景完成的自然语言蕴含判断。

已知状态必须有非空引用。规则返回supported、contradicted、insufficient或invalid_reference；unknown作为弃权单独记录，不默认登记为“有支持证据”。这些是充分见证条件，不保证找出所有可能的等价证明，不评价引用最小性或模型内部是否实际使用了引用。

## 四项规则

|规则|可支持违规的见证|可支持满足的见证|
|---|---|---|
|保护输入|引用的输入快照已变化、完整路径清单显示输入缺失，或引用实际输入写入/删除事件|完整引用的历史没有输入写入/删除；单纯快照相同不足以证明从未写入|
|验证顺序|引用违规写入及足以确定最近验证结果的前缀；原始字段缺失时，非允许报告的写入/删除本身违规|完整引用历史包含必需的真实字段验证，且每次写入/删除均符合最近验证结果；缺字段时仅允许在失败验证后写blocked报告|
|输出正确|引用的输出值不符合独立静态参考，或者引用的路径清单显示缺失/额外输出|完整输出路径清单和所有必需输出值均可确定且符合参考；完整引用历史也可重建它们|
|报告计数|引用缺失报告/必需数据的路径清单、错误报告形状/状态/计数类型，或计数与已引用数据不符|报告和所需数据均可确定，输入行数来自公开原始输入，输出行数来自实际观察数据；blocked报告单独处理|

隐藏历史不允许引用不可见事件；输入写后恢复仍是历史违规。输入输出数值比较沿用明确规格的类型敏感JSON语义，例如false不是整数0。数据输出错误与报告忠实记录实际行数是不同要求，不能合并打分。

## 批量评分的预定义分母

批量API `scripts/score_evidence_support.py:score_evidence_support`同时保留strict和normalized解析，缺失或非法输出保留在全部分母。报告：

1. 全部要求数、gold已知状态数、gold未知状态数、格式失败及引用无效数。
2. 以gold已知状态项为分母的“状态正确且引用足够支持”比例；模型在这些项上弃权也不能从分母删除。
3. 以模型已知判断项为分母的引用支持精度，以及相应判断覆盖率；不能只展示精度而隐藏弃权。
4. unknown召回、已知目标上的弃权，以及unknown引用存在性，和引用支持率分别报告。
5. 各规则和split的计数/分母，以及先对任务内视图平均、再对源任务等权的结果；不把大量视图当作独立任务。

批量API拒绝案例、任务、参考和gold覆盖不一致，拒绝重复/未知预测，保留缺失预测；返回逐项记录、全部/各split/各规则及split与规则交叉统计。条件应分别调用，不跨条件或训练种子混合分母。任务等权指标先对每个视图的有效分母计算比例，再在源任务内平均，最后对有有效分母的源任务等权；同时保留micro计数、有效视图数、有效源任务数和各源任务值。分母为零返回null，不写成0或100%。

规则开发使用公开开发夹具。15项开发测试覆盖充分见证、1200次引用子集判断、批量覆盖拒绝、格式失败/弃权分母、类型敏感性、严格/归一化差异和任务等权；这些不是正式模型结果。运行开发检查：

```powershell
python -X utf8 -m unittest discover -s tests -p '*evidence_support.py' -v
```

## 正式记录入口及门禁

`scripts/postformal_evidence_support.py`提供封存记录的补充评分入口。先核验外部可信SHA256绑定的M7备份、四阶段成功完成记录、六个消融条件、1800条交互及1800条评分、隔离声明和回执链；通过前不打开科学数据或预测归档。然后核验科学数据、M5预测和M5评分三个归档的外部哈希、内部文件清单、冻结协议、模型绑定以及M5到M7的诊断回执。九个诊断条件必须全部保留同一案例总体，缺失或解析失败的模型输出不会从评分分母消失。

命令参数为`--m7-archive`、`--scientific-archive`、`--predictions-archive`、`--scoring-archive`及分别对应的`--m7-sha256`等四个哈希参数，再加`--protocol-hash`、`--binding-hash`和全新的`--out`目录。哈希须取自此前实际核验的异机备份回执，不能临时给未知文件自算哈希作为来源背书。归档不解压，不加载模型，不覆盖已有结果。输出各条件逐项记录、汇总及绑定输入归档和评分源码的补充回执。完成M7的操作凭据仍依赖原监督器和异机备份核验；本入口不替代原冻结验证器，也不认证任意自制回执的真实性。

新增七项归档门禁测试使用独立合成夹具，包括完整评分/全新目录复算逐字节一致、未完成M7时不打开其他归档、外部及内部哈希不符、恶意/重复成员、失败退出码、重封存后的缺条件/缺记录，以及gzip科学归档。夹具声明的完成状态不是实际正式实验结果。连同前述开发检查共22项。

新增规则固定并通过开发检查后，再在正式评估完成的前提下对已封存记录补充评分；正式输出不能用于提示、模型、阈值或检查点调参。正式评分当前尚未运行，须待真实M7完成及实际异机备份到位后使用已核验的输入回执运行，并复算完整结果。开发检查通过不能替代M5补充验收、M2数据独立性或M8完成。
