# 顺序违规补齐与程序标签对抗检查

2026-10-23。用户已批准完全程序标签路线。本轮解决M2h中R_ORDER没有violated的候选覆盖缺口，不修改正式测试或训练视图选择。

## 新增候选

在相同600份train合同及固定静态参考上，每份生成12个故障视图，共7200个；原2400视图原封不动保留为前缀，合并候选池9600视图。源任务分组、模板、操作族及划分保持原样，新增独立任务为0，仍只有一个共享模板。

场景包括：先写后验、完全不校验、错误输出类型、报告数字写成字符串/布尔、删除输入再恢复、校验前修改并恢复、结果错误但报告计数真实、额外产物、删除输出、删除报告、历史隐藏且输入快照已改变。缺必需字段的blocked分支不在本矩阵覆盖内，程序明确拒绝这类输入，不静默声称已测试。

| 要求 | satisfied | violated | unknown |
| --- | ---: | ---: | ---: |
| 输入保护 | 6600 | 2400 | 600 |
| 校验顺序 | 6600 | 1800 | 1200 |
| 结果正确 | 6600 | 3000 | 0 |
| 报告真实 | 6000 | 3600 | 0 |

顺序违规1800视图来自先写后验、无校验、校验前修改/恢复三类，各600。同源多视图不是独立统计样本。unknown仅在规格和观察确有证据缺口时使用；完整快照足以判定的缺文件不人为标成unknown。

## 独立场景预期与变异检查

故障生成器不读取模型输出，也不调用在线求解/分析器。场景预期在代码中独立固定，离线标签器对7200视图的28800项状态均符合预期。生成器使用静态参考构造正常产物，再通过可信虚拟工具注入动作；参考正确性仍须由其他证据支持。

另外，在隔离命名空间中对版本化离线标签器施加六种明确修改，保留原生产模块，不执行任务文本或模型代码：

| 主动引入的错误 | 被检测的视图数 |
| --- | ---: |
| 忽略恢复前的输入写入 | 1200 |
| 只检查最终有校验、忽略写入顺序 | 1200 |
| 历史隐藏仍判顺序安全 | 600 |
| 忽略额外产物 | 600 |
| 无条件判报告正确 | 3000 |
| 使用宽松JSON相等、混淆布尔和整数 | 585 |

六种变异均存在反例，结果说明这些测试对所声明错误敏感。不是穷尽验证、形式化证明、真实模型准确率或所有代码变异均可检出的保证。585与600的差别来自宽松比较只在部分计数值上误判，不能把未改变的视图删除后报告。

9600视图是开发候选池，不表示全部必须进入正式训练；最终视图配额、类别分布、长度和监督token预算须在开发阶段选择并冻结。不得依据新测试表现筛选。新增轨迹更长，旧2400视图的上下文测量不能外推。单模板、新test/OOD、自然轨迹覆盖、blocked分支、程序协议迁移和正式资源预算仍待补齐，正式训练未启动。
