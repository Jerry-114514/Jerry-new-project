# 单 GPU 独占保护与失败运行审计

日期：2026-10-22。属于 M1 工程与 M8 失败记录保存，不是正式实验或新一轮训练。

## 已查明的失败

AutoDL 上两个额外开发运行各有 32 条记录，所有记录均失败，不能把 manifest 的 completed 理解为实验成功。

| 开发运行 | 记录数 | 失败原因 | 解释边界 |
| --- | ---: | --- | --- |
| 微调 3B 执行器 + 公开规则分析器 | 32 | 16 条动作 Schema 错误，16 条不是有效 JSON 提议 | 不证明分析器或控制器无效；执行接口未通过 |
| 官方原始 9B 执行器 + 3B 分析器 | 32 | CUDA OOM，所有调用前计费 token 为 0 | 与另一 9B 开发进程同时占卡，不证明独占 5090 无法运行 |

3B 首条原始输出包含 `{"op":"validate"}`，遗漏必需的布尔 ok；写入路径形如 `/[0]/price`，是 JSON Pointer，无法作为工具的相对文件路径。这是模型未遵守公开接口。不能通过自动补 ok、猜测文件路径或放松安全检查，把失败改成执行成功；后续若调整提示、格式反馈或再训练，必须作为单独开发版本保存成本与结果。

OOM 记录明确出现 PID 57889 占约 17.96 GiB，同时另一进程已占约 13.38 GiB。57889 正是本线程的混合分析验证进程；该验证启动时检查过显卡空闲，但另一项旧入口实验随后启动。两项运行缺少共同排他机制，导致争用。失败记录保留，不能仅根据 OOM 删除样本或宣称硬件容量不足。

目录中的 `formal-m4-*` / `formal-m5-*` 是这些额外运行的路径名，**不是 idea.md 正式 M4/M5 的完成证据**。它们使用公开开发任务，3B 也不替代正式方案指定的官方原始 9B 六次训练。

## 已实现的独占保护

新的 CUDA 入口使用进程级内核文件锁。Linux/AutoDL 固定锁文件为 `/tmp/intentlab-cuda.lease`；当前单 GPU 实例只允许一个受管 CUDA 实验，不按输出目录各自加锁。第二项受管运行在导入 ML 依赖或加载模型前拒绝，不会等到整组任务全部 OOM。

锁覆盖整个进程，包括角色卸载与重载的间隙；调用 backend.close 不提前释放实验租约。正常退出或进程崩溃后由系统释放；持久文件及其中 PID 仅作诊断，不能据此判定任务仍在运行，也不删除锁文件来“恢复”，以免两个 inode 同时被锁。子进程不能继承父进程的运行授权。

LocalBackend、LocalModelPool 和训练器均接入。每次推理及每个训练更新前还检查 `nvidia-smi` 的 CUDA compute PID，允许自己，拒绝其他进程；查询失败也拒绝，不将未知状态视为空闲。CPU 运行不占 GPU 锁。

这是协作保护，不是对任意外部程序的系统级禁用。未更新的旧工作树或外部程序仍可能在检查后启动 CUDA，因此后续任务应从同一个已更新入口串行运行。检测到外部占用时不杀别人的进程，不自动重试失败组；确认原任务终止后另开新输出目录，保留旧错误。

占用查询增加少量开销，正式条件必须使用相同保护并计入墙钟；不能直接与旧无保护运行比较速度。当前实现保守地按实例全局排他，针对本方案的单张 5090，不声称是多 GPU 调度器。

## 验证和证据

本地完整 114 项测试通过 107 项、7 项因无 ML 依赖跳过；AutoDL 全部 114 项通过。新增测试使用真正竞争的子进程验证排他、强制终止后的内核释放、旧 CUDA 进程检查、查询失败关闭及加载前拒绝。

另在 AutoDL 只创建本审计自己的微小 CUDA 张量：不持锁 CUDA 子进程被检测并拒绝；持锁时第二个 LocalBackend 构造在加载前被拒绝；持锁者可以分配 CUDA 张量并重复检查。未加载 9B、未训练、未停止其他实验。命令：

```bash
python scripts/audit_gpu_lease.py --out runs/resource-check/gpu-lease-audit.json
```

先确认无其他运行，再执行上述检查；输出文件不能覆盖。锁与实际 CUDA 进程均空闲是启动条件，不以旧日志的 completed 或锁文件存在性代替实时核验。

两组共 64 条旧失败记录均通过独立工具重放、指标与预算复算。它们的当时源码和环境未事先冻结，因此不声称能精确重现原始生成；新 GPU 审计保存了对应源码指纹。原始记录及测试见 [结果包](../examples/results/formal-m1g-resource-audit/README.md)。

在仓库根目录运行 `python scripts/audit_resource_failures.py` 可从原始记录重新核对 64 条失败、原因及全部指标/预算，并生成逐文件校验值。实际 GPU 检查需在空闲 AutoDL 上重新运行，不由 JSON 文件的存在代替。
