# WikiSQL 来源的显式合同开发适配

日期：2026-10-23。此批次推进 M2 候选构建，不完成正式数据、训练或闭环效果验证。

## 已构建内容

在固定版本的 600 条上游 train 来源池中，选取无聚合、单个文本等值条件、具有 page_id 且谓词值和单元格均为可打印 ASCII 的记录。按既有确定顺序选择，排除相同 page_id 或相同表格内容，得到 12 份训练开发合同。它们共享一个项目模板；12 个不同 page_id 只是暂定来源分组，不是独立性证明。

上游问题保留为背景。协调人从上游 SQL 标注提取筛选列、筛选值和投影列，**作为新增公开要求写入每个模型都能看到的请求**。模型负责按显式规格处理文件、遵守输入保护及先校验后写入、生成结果和计数报告。这改变了任务：不是复现原 WikiSQL 自然语言转 SQL，也不能用结果报告原题求解准确率。人工须检查新增要求的含义、背景与要求是否冲突、适配来源及授权。

新增公开操作 `ascii_filter_project` 只接受可打印 ASCII 谓词，执行大小写无关筛选并保留原行顺序、重复项和所选 JSON 值类型。候选离线参考由另一实现通过参数化 SQLite 查询生成，不调用公开转换函数、不执行上游 SQL 文本。域限制与 [SQLite 的 NOCASE 规则](https://www.sqlite.org/datatype3.html#collating_sequences)相匹配；可打印字符限制也排除 NUL。两份程序对同一规格的一致性只能证明实现吻合，不能代替人工参考核验。

每份合同生成四个注入证据视图，共 48 个；轨迹不是自然模型错误。案例使用不含故障名称的不透明 ID，故障映射仅协调人持有。初版私有构建保留作历史，新版在任何分发之前修正 ID；两版不能当成新增样本相加。真实模型的两次执行另行保存，不混入这 48 个注入视图。

## 实测证据与限制

- AutoDL 195 项测试全部通过；本地运行 195 项，其中 185 项通过、10 项模型环境相关测试跳过。
- AutoDL 与本地的 111 份规范化源码指纹一致；私有构建的 8 个文件字节指纹一致。
- 12 份合同的公开程序输出与独立编码的 SQLite 候选参考一致；这不是人工正确率。
- 官方原始 Qwen3.5-9B 对首两份合同实际执行，4 次模型调用，程序异常 0。候选参考下 1 题合规、1 题未完成。四次调用均使用既有格式投影；不能记为原始严格接口通过。
- 首次启动在加载模型前被 GPU 占用检查拦截，失败日志保留。观察到对应 PID 已消失且 compute 列表为空后才重试，未终止其他进程；不推断进程归属，也不将该失败写成显存不足。
- 本次没有修复、训练后的分析器或正式四条件比较。人工准确率为 null，M4/M6 均未完成。

元数据和失败日志见 [M2d 证据目录](../examples/results/formal-m2d-wikisql-adaptation/README.md)。原题、表格、候选答案、案例、故障映射和模型原文留在被忽略的私有目录；仓库仅发布代码及元数据。

## 复核命令

以下在仓库根目录运行。审计输出只有元数据；后两条须提供私有输入，均不执行新模型推理。

```bash
python examples/results/formal-m2d-wikisql-adaptation/audit.py
python examples/results/formal-m2d-wikisql-adaptation/audit.py --archive /private/data.tar.bz2
python examples/results/formal-m2d-wikisql-adaptation/audit.py --archive /private/data.tar.bz2 --private-smoke /private/private-smoke
```

原始模型回放会重建实际提示并核验 prompt 哈希，复现格式解析、工具动作、分析及指标；不是重新生成输出。仍需扩充多领域来源、独立自然错误和新隔离 test/OOD、人工审查、开发功效分析及冻结。不得把这一个公开基准衍生模板扩写成正式目标规模。
