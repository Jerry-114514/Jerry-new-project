# 基线完成后的单次顺序任务

2026-10-23。为避免开发GPU任务结束后等待人工衔接，已启动单次顺序执行器。它当前只等待已验证存活的基线进程，不占用第二份模型或启动第二个GPU任务。发布时1800次基线仍未全部完成；本文件和launch snapshot不是评分或采集结果。

顺序固定为：

1. 绑定基线PID、Linux进程启动tick及实际命令行，等待该进程退出。记录仍为running的文件不作为存活证据；PID复用或命令身份改变时停止。僵尸进程视为已退出。
2. 要求实际生成清单completed，A/B3/B4各600份原始预测完整；原评分器再检查预先记录的输入及输出哈希，之后统一评分。评分目录已有结果时停止，不覆盖或自动重评。
3. 核对已固定32源的自然采集计划、任务/参考哈希及全部官方模型资产，依原计划用官方原始9B、none策略、最多三步反馈采集自然轨迹。
4. 采集进程退出后，使用已绑定哈希的程序标签入口导出64个预期可见性视图，保留失败，并记录实际数量。数量必须以实际结果为准。

任一步异常都留下failed状态及日志，停止后继，不重试前驱、不重启基线、不另起替代目录。等待上限六小时只限制依赖等待；超时不会杀死前驱或启动后续GPU工作。执行目录拒绝覆盖，所有阶段仍属于开发，不是正式六次训练。

AutoDL执行源码固定在b4a757a的干净检出，保证正在运行的基线和随后的旧执行器行为不因本地新增代码变化。新增顺序驱动、评分器及程序标签入口放在该检出之外并绑定SHA256；每阶段前重查源码/输入。队列运行期间不要更新这个规范检出的HEAD；新研究代码照常在GitHub保存，待本顺序任务结束再部署。

本地五项针对性测试覆盖Linux进程名含括号/空格、PID复用、命令变化、僵尸状态、前驱失败及completed声明但原始记录不完整时拒绝启动后继。全套243项测试含14项ML跳过，其余通过。测试不代替真实队列完成；实际队列已核验PID存活、通过外部文件哈希预检并处于waiting_for_baseline阶段。
