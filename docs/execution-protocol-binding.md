# v2 正式协议：执行任务、参考答案与控制条件绑定

日期：2026-10-22。对应 idea.md 的 M1/M3/M6/M7。本文是工程接口说明；正式数据、真实人工审核、功效与预算证据尚未满足，协议未冻结，也没有启动六次正式训练或正式闭环。

## 为什么增加 v2

旧 v1 协议记录了 A–E/P1–P4 名称和训练设置，但没有绑定实际闭环任务、独立静态参考、分析器选择及动态 k 参数，仅凭该锁不能证明执行条件已冻结。

现在正式冻结要求 schema_version=2；旧 v1 仅保留工程兼容。v2 草案增加 execution 字段，将执行输入、设置及结构化执行/oracle 审核与诊断数据绑定。旧实验、原始结果和源代码快照不改写。

正式 source_root 必须就是当前加载协议实现的干净 Git 检出，不能从新代码运行冻结器却将另一份旧工作树记作执行源码；正式验证也会核对实际加载位置。

## 固定哪些内容

| 内容 | 冻结前校验 | 训练验证是否读取其文件 |
| --- | --- | --- |
| 执行任务 tasks | 每个已审核 test/OOD 公开合同变体恰有一个执行任务；源分组、请求、原始输入、要求及公开规格一致 | 否 |
| 独立 references | 每任务一个静态参考，路径和结构符合公开合同；不调用公共解题器为自己背书 | 否 |
| 执行/oracle 审核 | 精确 task/reference 哈希、逐任务两位不同人员的真实合同与参考核验声明 | 否 |
| 分析器选择 | D/E 条件、配对种子之一、只按 best_validation_loss 选检查点 | 只读取锁内设置；不读取执行参考 |
| P1–P4 | 两组 fixed-full、两组 dynamic-k；硬检查依次关闭/关闭/开启/开启 | 只读取设置 |
| k 消融与工具接口 | 显式严重程度映射、1 至 max_k 的全部固定对照、工具步骤上限、包格式处理、历史可见性 | 只读取设置 |

正式 token、上下文、输出和修复轮数沿用同一主协议 budgets，不另设可以悄悄覆盖的执行预算。后续正式执行器仍须按这些设置运行并核验实际账本。

执行任务应覆盖诊断数据中全部 test/OOD 源组的公开合同变体；同一合同的多个证据视图只对应一个执行任务，同源的改写等已审核变体可以分别执行，但仍留在同一源组，不能算作独立任务。不能拿开发任务重新命名、修改输入或要求后冒充已审核测试任务。程序验证精确分组和内容一致，语义近重复与来源独立性仍须人工审核。

## 参考答案审核与诊断标注分开

[人工标注流程说明](human-annotation-workflow.md)用于“可见视图内要求状态”的双人独立标注。那份盲包不应附带 oracle 或静态参考。本节审核的是公开任务合同及**拟作为离线真值的静态输出**，属于数据构建和 oracle 审核，不能与诊断盲包混发。

协调人向合同/参考审核者分别提供同版公开 tasks 和独立 references，请其核对操作、所有记录、边界、类型、报告及约束含义，并记录核算依据。不得只运行已有公共 solver、自动得到通过结果后就署名为人工核验；公共规则实现与离线参考可能各自有错。

可以复用真实 A/B 人员，但应先锁定其独立诊断初审，再开展该项审核，避免拟定参考反向影响初审一致率。审核分歧先保留、澄清并修订有问题的任务/参考，再真实复核新版；不能把未解决的分歧写成两个 true。变更涉及诊断案例时，该案例也必须按版本重新审核。

把实际审核结果汇总到主协议 evidence.execution_and_oracle_audit 指向的 JSON。它需包含 schema_version、tasks_hash、references_hash、reviews，哈希按以下方式计算：

```python
from intentlab.core import digest
from intentlab.execution_data import load_execution_tasks, load_references

tasks = load_execution_tasks("runs/formal-private/execution/tasks.jsonl")
references = load_references("runs/formal-private/execution/offline-references.jsonl", tasks)
print(digest(tasks))
print(digest(references))
```

以下仅为**未填写模板**，不是审核证据，不可直接通过冻结：

```json
{
  "schema_version": 1,
  "tasks_hash": "待填写实际哈希",
  "references_hash": "待填写实际哈希",
  "reviews": [
    {
      "task_id": "待填写真实任务ID",
      "reviewer": "",
      "human_verified": false,
      "contract_verified": false,
      "reference_verified": false,
      "notes": ""
    }
  ]
}
```

每个 task_id 恰有两条不同真实人员的记录；三项布尔标志均须在实际检查后才填 true，notes 非空并说明核算依据。缺人、重复人员、未核验、缺任务或参考内容变化都会拒绝。工具检查的是声明和文件一致性，不能认证真人或替代质量抽检；真实身份映射与原始独立审核记录仍由协调人保管。

## 设置与隔离

草案中的 D、seed 0、model 模式、max_k=3、0.25/0.5 阈值等是待开发验证的起点，未被正式选择，也不代表训练已完成。冻结前确定实际配置；看过测试结果后不能改选择或将 model 改成 hybrid 再声称是同一确认性条件。

model/hybrid 必须显式指定。当前可执行合同的 hybrid 门控实质由公共规则负责，需单独解释其科学含义，不能将其当微调模型判断改善。P1–P4 必须共用相同分析器、原始执行模型、预算、事件可见性和包处理；只按登记的策略和硬检查开关区分。

检查点的具体权重在训练后才存在；v2 此处先绑定选择规则，不预先虚构适配器哈希。后续还需核验六组矩阵完成记录，绑定实际验证所选模型文件及其哈希，再锁定推理与测试揭晓入口。目前开发 execution CLI 仍拒绝 test/OOD，不能凭 v2 就绕过这一限制。

运行主协议的 check/freeze/verify 命令与[冻结指南](formal-protocol-guide.md)相同。freeze 在协调/数据审核环境中读取完整材料，保存执行文件路径、SHA256、源组摘要和 P1–P4 映射。若审核文件或执行输入在冻结期间改变则拒绝。

verify --phase training 不打开执行 tasks、references 或执行审核，也不打开测试 gold/人工初审；只检查训练可见资产和锁内设置。删除这些隐藏文件后，训练校验仍应成立；verify --phase all 属于协调/离线审计，会读取全部封存材料并重新匹配执行合同。它不能作为在线分析器读取答案的入口。

## 验证与未完成事项

单元测试使用明确的工程夹具、假模型和合成署名，不是实际人工交付。覆盖 v2 成功冻结、训练不读取参考、参考变更拒绝、即使更新哈希也不能偷换公开输入、重复/未核验人员拒绝、测试损失选模型拒绝、漏固定 k 对照拒绝及旧正式 v1 拒绝。

AutoDL 最终全部 124 项测试通过，本地 116 项通过、8 项无 ML 依赖跳过。除校验测试外，还实际运行 v2 的六组微型 CPU 训练及一次中断恢复，共七次子进程启动；先删除执行任务、参考、审核及测试 gold，所有训练仍完成。三个种子配对暴露一致，每组仅四次样本暴露、208 个监督 token，不是正式 9B 训练。日志、冻结元数据和结果复算见 [工程证据](../examples/results/formal-m1h-execution-binding/README.md)。

此实现完成的是正式冻结输入绑定。实际新数据、人工审核、科学审核、权重选择绑定、正式执行入口、一次性测试揭晓、四组真实闭环及消融/统计仍需继续完成；不能把本页工具测试作为 M3/M6/M7 完成证据。
