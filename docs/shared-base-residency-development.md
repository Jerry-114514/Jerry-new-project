# 共享底座的开发验证与预算约束

最新状态：实际9B核验已完成且输出/原始tokens/账本/资产一致，耗时69.35秒对38.40秒；范围仍仅限两条开发输入与每调用128新tokens，不证明全阶段固定收益。[原始证据与资源事故补救](gpu-interference-incident.md)同时说明此前固定k开发比较不可采用的独立原因。下文待测描述保留为最初开发时点记录；正式常驻政策仍未启用。

2026-10-23。用户已提供实例小时单价和本轮预算上限，私有运行账目按当前容器已运行时间保守计入历史费用，并保留关机余量。该估算不是 AutoDL 发票；守护进程已核实存活，费用到阈值时尝试中断本研究进程并关机。公开仓库不发布用户金额、认证材料或账目。此前约100–190小时的剩余阶段估计，上沿超过现有额度，因此不能承诺全部阶段已获资源保障。

原实现中，actor 是官方完整权重、analyzer 是其 LoRA 时，两条路径交替会重复装载底座。新增 `LocalModelPool(..., share_base_adapter=True)` 作为默认关闭的开发选项：符合条件时只常驻一个未合并底座和分析适配器，actor 在 PEFT `disable_adapter()` 上下文内执行，analyzer 使用启用的适配器。依据是 [PEFT 官方接口](https://huggingface.co/docs/peft/main/package_reference/peft_model)。两角色分别载入自己的 tokenizer、pad/EOS 策略，继续使用原始严格预算和失败预留计费；不共享跨调用 KV cache、输入或输出。每任务 reset 清空账本与调用记录，保留权重。

仅当分析器明确指向执行器的绝对本地底座路径，且是没有训练 bias、modules_to_save、额外可训练 token、层复制或变更底座初始化的 LoRA 时才允许共享。独立底座、tiny recipe、非 LoRA 等情况保留原重载路径；注入测试工厂不改变行为。不合资格不宣称获得加载节省。现有正式 M6/M7 入口仍保持逐任务冷启动，不自动采用该选项。

开发检查使用真实随机微型 GPT-2 及非零 LoRA，逐次比较“actor→analyzer→actor”和各角色重新加载的生成及 token 计费；额外保留两个角色不同的特殊 token 配置。检查原始生成 token 序列、输出、除时间外的完整账本、启用/禁用适配器后的不同 logits，以及失败后适配器恢复、超限拒绝、模型张量不变、任务 reset 后复用及 close 释放。随机权重和注入故障只验证工程行为，不证明任务质量。初次夹具未从已保存本地底座重新加载，适配器缺少匹配的底座身份，正确被资格检查拒绝；修正夹具后两项针对性检查通过。首次失败日志保留，不删除失败或放宽资格要求来通过。

本地276项检查包含16项可选ML跳过，其余通过。服务器完整ML环境全部276项通过、无跳过，测试日志约135.92秒，驱动总计137.45秒；CUDA_VISIBLE_DEVICES为空，未占用GPU。最终检查记录见[原始证据](../examples/results/formal-m3y-shared-residency/README.md)。该路径尚未完成实际9B等价性、显存和耗时测量；没有据此调低总预算估计或填入正式就绪证明。

下一步在450次固定k开发任务全部结束、GPU租约释放后，用官方原始权重和已有长历史压力实验适配器，在开发输入上复核共享与重载的原始 tokens、角色账本、峰值显存及真实加载时间。保持该压力适配器的工程身份，不替代正式训练端点。如果通过，再在测试模型输出生成前明确修改并冻结统一常驻/计时政策，给所有条件采用相同规则；条件间冷启动，任务间只复用权重，加载成本和推理成本分别记载。当前没有实施这项正式政策变更，也没有证明整套实验能在剩余额度内完成。六组训练、四组闭环和预登记消融保持原规模。
