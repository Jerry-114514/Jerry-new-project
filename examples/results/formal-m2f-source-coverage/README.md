# M2f：跨批来源、模板及既往公开资产清单

固定输入为旧 32 个开发视图、WikiSQL 显式合同的 48 个注入视图及同源 24 个自然视图。104 个唯一视图合并为 32 份合同、24 个声明来源 ID；源 ID 和合同均没有经人工证明独立。自然/注入视图不增加独立样本数。

自动标记 78 对来源/模板/操作风险，其中 12 对跨 train/validation；共同编码操作不等于已证明重复。WikiSQL 的 12 份合同共享一个模板，66 对均被标记共同模板风险。未标记也不证明独立。

`summary.json` 绑定三个输入批次、合同库存及风险队列；`contracts-index.jsonl` 去除原文、输入和来源内容，只保留合同哈希及分组计数；`candidate-pairs.jsonl` 是风险元数据。`semantic-review-template.json` 为协调人来源审查空表，不是逐要求诊断标签，不应发给盲标初审人。

`prior-public-inventory.json` 固定提交 `65f35a9` 下 data/ 和 examples/results/ 的 1,034 个 JSON/JSONL 路径、Git blob SHA 和字节数；它包括元数据和重复拷贝，不是 1,034 套数据。没有审阅这些文件的全部内容，也未覆盖 Markdown、日志、未跟踪文件、其他仓库或预训练语料。

完整合同、来源及协调人材料仅在私有包中；包含自动清单和 24 个来源组、78 对风险的空白审核表，尚未分发或审核。`coordinator-package.json` 绑定 8 个私有文件及压缩包，不对独立性作背书。

`audit.py` 默认核对公开元数据及固定 Git 树路径目录。提供 `--injected PATH --natural-root DIR` 时，重新读取私有注入和自然协调人案例，复现合同与风险队列，并验证空白审核无法通过正式人审校验。它不读 oracle、模型输出、指标或人工标签，也不推断真实审核身份。

M2、M3 及正式数据冻结未完成。新来源、更丰富模板、真实来源/语义核验、双人状态标注和新的隔离测试/OOD 仍须建设。详见[跨批来源覆盖说明](../../../docs/combined-source-coverage.md)。
