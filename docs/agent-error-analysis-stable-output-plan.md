# Agent 误差分析与纠偏：稳定成果产出导向的研究方案

日期：2026-10-20

版本：第二份建议报告；在原研究建议基础上，补充误差分析器、多维评分及不依赖正向性能提升的成果路径。

前序报告：[面向多步骤 Agent 的用户要求保真与证据驱动纠偏](agent-intent-fidelity-research-proposal.md)

状态：研究设计，尚未实现本报告中的任务集、验证器和实验；本文没有新增实验结果。

## 执行结论

**当前方案没有任何部分能够保证方法提升、统计显著、新颖性或论文录用。可以通过明确范围、验收条件和资源安排，提高可复现研究产物的交付确定性。**

原方案主要依赖“分析、打分和复检能改善 Agent 表现”的假设。若假设不成立，原型虽然能够运行，也可能缺少足够扎实的研究结论。建议增加一条独立的测量与诊断路线，使项目无论得到正向、负向还是不确定结果，都能交付可核查的数据、工具与分析。

推荐按以下顺序推进：

1. **先完成可控交付：** 可重置任务环境、逐项真值、独立验证器、轨迹数据和复现协议。
2. **再完成诊断交付：** 测量要求解析错误、错误放心、修复退化以及内部评分的有效性。
3. **补充条件性分析：** 在明确假设下，证明修复接受规则对已检查约束的保持性质，并用反例展示假设失效的边界。
4. **最后争取方法提升：** 在同预算下比较简单提醒、误差分析、多维评分与修复复检。

“稳定产出”在本报告中指达到质量门槛的可复现产物与诚实的结论，不等于保证发现新现象，也不等于保证发表。

## 1. 原方案的成果稳定性审计

| 工作部分 | 可控交付 | 依赖实验的结论 | 稳定性判断与改进 |
| --- | --- | --- | --- |
| 要求结构化与追踪 | 要求格式、来源记录、状态机 | 自动解析是否足够保真 | 工程交付较可控；增加人工真值和漏项、过强约束诊断 |
| 误差分析器 | 可运行分析接口与证据引用 | 是否准确、是否超过简单规则 | 原型可控；研究结果须独立评估 |
| 多维打分 | 评分规则与逐项记录 | 分数是否预测真实质量、能否改善决策 | 存在评分无效风险；增加固定候选集上的离线检验 |
| 候选修复与复检 | 生成、检查、接受与拒绝机制 | 是否减少退化且不损害完成率 | 有清晰机制，但性能增益不保证 |
| 动态检查调度 | 调度策略与成本记录 | 是否优于固定检查 | 高依赖任务分布，推迟至后期 |
| 跨任务、跨模型泛化 | 评测协议和完整结果 | 收益是否稳定泛化 | 成本较高，不能作为首个交付前提 |

最应补充的不是更多 Agent，而是：**独立测量工具、控制变量实验、条件性保持分析和结果不显著时的报告路径。**

## 2. 文献定位与新增内容的边界

已有工作为本方案提供基础，也限制了可宣称的新颖性：

- AgentIF 已提供复杂要求的逐项评估，不能仅以“有要求清单和约束指标”作为贡献。[1]
- CCTU 已涉及逐步可执行验证与违规反馈，并报告其设置中的修复困难；本方案须进一步分离检查错误、反馈作用和修复退化。[2]
- GuardAgent 已涉及文字要求到可执行检查；新增价值应落在独立质量评估及闭环行为上。[3]
- ARTEMIS 已涉及自然语言要求形式化与可区分轨迹验证；受控反例及规格验证并非全新概念。[4]
- AgentSpec 和 Agent-C 已研究运行时约束执行；本报告的条件性保持性质只能是方法正确性说明，不能自动视作理论创新。[5][6]

**候选差异：** 在同一可重置环境中，将要求错误、执行错误、证据可见性、评分决策和修复退化连接到独立真值，分析闭环何时有效、何时无效。

该差异仍需通过进一步全文核查、公开实现对比和实际实验确立。初步文献检索不能证明不存在相同研究。

## 3. 补充一：可复现任务与验证资产

### 3.1 范围控制

第一阶段仅研究本地文件和结构化数据任务。工具通过受控接口运行，环境能够恢复初态，禁止未记录的外部副作用。暂不将网页操作、真实账户操作或不可撤销外部写入纳入保持性质的适用范围。

要求以用户明确表达的内容及有效修订为准；附件或工具返回中的文字保留来源，不自动视作用户指令。

### 3.2 最小任务包

先制作 40 个开发与先导任务，覆盖合并去重、筛选、字段校验、格式转换、分组统计、多文件交付六类操作。每项任务至少包含一个可独立验证的硬约束，并按条件要求、时序要求、交付要求分层覆盖。

每个任务包包含：

| 文件或记录 | 内容 |
| --- | --- |
| 请求 | 原文、要求出处、适用条件 |
| 环境初态 | 输入文件、版本、哈希与工具状态 |
| 标准要求表 | 人工核验的逐项语义和验证方式 |
| 独立验证器 | 环境状态检查、顺序检查及交付检查 |
| 合法参考执行 | 至少一条能完成任务且遵守要求的轨迹 |
| 重置与复现说明 | 环境恢复、运行配置、失败处理 |

任务、验证器和参考执行不能仅由同一个模型生成并自我确认。开发者完成后，由另一名核验者审查关键要求和边界；若没有第二名核验者，应明确记录限制，不宣称已完成独立人工核验。

### 3.3 验收标准

- 每项任务存在经过核验的合法完成路径，避免把不可满足任务当作模型失败。
- 从相同初态重放固定动作序列，得到相同的验证结果。
- 验证器接受合法实现，并拒绝针对约束构造的已知违反；同时加入不同写法的合法实现，排查过度约束。
- 任务数据记录版本和来源，报告实际覆盖范围；不将 40 个任务称为充分代表真实世界的大型基准。
- 系统内部检查器与最终验证器分离，不让被测系统读取隐藏标签、参考轨迹和最终评分代码。

**稳定成果：** 版本化任务包、逐项标注、独立验证工具及其已知边界。即使纠偏方法无提升，这些资产仍能交付；是否足以成为独立学术贡献，取决于质量、差异和覆盖。

## 4. 补充二：不依赖在线收益的受控诊断实验

### 4.1 轨迹构造

在每个先导任务上构建四类实际可重放的轨迹：

1. 合法完成轨迹。
2. 注入一项明确违规的轨迹。
3. 从违规状态出发、修复目标且保持其他有效要求的轨迹。
4. 修复目标但破坏另一项原已满足要求的轨迹。

目标规模为 40 × 4 = 160 条轨迹。若任务不适合某类变异，应报告缺失原因或在开发阶段修改任务，不得伪造可执行性。

变异应实际执行并由独立验证器确认后果，而不只是编辑日志文字。变异类型轮换覆盖覆盖输入、错误保留记录、漏条件、顺序错误、字段遗漏和格式修复引起的内容丢失。

### 4.2 证据可见性的配对处理

给同一真实轨迹提供完整证据和删减证据两个版本，共最多 320 个评判视图。证据删减不改变实际行为；最终标签仍以完整环境真值为准。

这些视图属于相同任务和轨迹的重复测量，不能当作 320 个独立任务。其结果估计的是所构造诊断分布下的表现，不能推断真实部署中的错误发生频率。

### 4.3 比较与指标

比较简单规则检查、只读最终回复的模型检查、读取原文与执行证据的模型检查。记录：

- 真实违规检出与合法轨迹误报。
- 真实违规被判为满足的“错误放心”。
- 证据不足时选择待判定的比例及已判定部分的错误率。
- 修复退化检出能力。
- 错误类型、证据引用和定位阶段的准确性。

最终应交付混淆矩阵、任务分层结果、证据配对差异、成本和典型反例。若所有方法接近满分，也应报告当前诊断任务过易或上限效应，不能强行得出新方法有效。

### 4.4 自然轨迹校验

受控变异可能留下易识别的痕迹。在线先导实验产生后，应额外分析自然失败和自然修复轨迹，比较两类错误是否一致。没有自然样本支持时，只报告受控诊断结果，不推广至实际错误分布。

**稳定成果：** 分析器能力边界、错误放心案例、退化检出结果和证据缺失敏感性。差异的方向与大小不可保证，但测量协议和完整结果可以预先规划。

## 5. 补充三：先验证分数，再让分数控制 Agent

### 5.1 分开三个对象

- **状态指标：** 硬约束违反数、要求满足率、证据覆盖与成本。
- **候选排序分数：** 在多个可选修复中决定先尝试哪个。
- **最终研究指标：** 独立验证的合规任务成功率与退化情况。

三者不能互相替代。内部得分提高但独立验证无改善，属于评分有效性未获支持。

### 5.2 固定候选集实验

先冻结同一个出错状态下的候选修复集合，再比较随机或固定顺序、简单严重程度排序、多维评分排序。标准答案排序仅用作诊断参照，不是可部署方法。

候选集合对各方法保持相同，避免把更强的候选生成误认为更好的评分。如果集合中没有合法修复，应单列为生成不足，不能归咎于排序器。缺少关键证据的候选可选择先验证，不强迫其获得确定分数。

测量首选候选的真实有效率、退化率、找到合法候选的尝试次数与成本。若报告概率置信度，另行评估其校准；若没有足够样本，不将模型自报置信度解释为正确概率。

### 5.3 简单决策规则优先

第一版采用预先固定的规则：优先排除已确认新增硬约束违反的候选；再优先选择修好目标且保持受保护要求的候选；满足程度相同时比较成本。

复杂可学习评分器、任意加权总分和动态预算调度暂不作为最低交付内容。如果简单规则已经达到同等表现，应保留简单方案并如实报告。

**稳定成果：** 评分是否具有排序价值的独立测量，以及评分失败和候选生成失败的分离诊断。

## 6. 补充四：条件性的约束保持分析

### 6.1 可证明的有限性质

设 K 是修复前已验证满足、且当前仍有效的受保护要求集合，V_i 是对应验证器。设候选修复产生状态 s'。接受规则为：

```text
仅当目标要求通过验证，并且对所有 i ∈ K 都有 V_i(s') = 通过，
才接受候选修复；否则拒绝或补充验证。
```

在以下假设同时成立时，可以直接推出：**被接受状态不会违反 K 中的要求。**

1. 验证器对这些要求是可靠的：通过意味着实际满足。仅此性质不要求验证器接受所有合法状态，但误拒绝会损害任务完成率。
2. 验证对象与实际提交状态一致，验证到提交期间没有未监测修改。
3. 所有相关副作用均被完整中介；候选操作在隔离环境执行，或可完整回滚。
4. K 覆盖研究声明所涉及的受保护要求，且不存在未处理的用户有效修订。
5. 对时序或历史要求，验证器检查完整相关轨迹，不能仅检查最终快照。

证明是接受规则与可靠验证器假设的直接推论，可以作为正确性说明。它不自动构成新的理论贡献，也不保证所有用户要求被正确解析，不保证找到修复，不保证任务完成，更不保证真实开放环境安全。

### 6.2 工程上检验性质边界

在隔离的文件环境中测试受保护输入保持不变、必需输出字段仍存在等性质，并为每项假设构造失效案例：

- 验证器漏检：修改未被检查的字段。
- 规格漏项：要求从 K 中缺失。
- 提交状态不一致：验证后再次改变内容。
- 未隔离副作用：候选执行时就改变了受保护输入。
- 历史不可恢复：先覆盖再恢复，最终哈希相同但已经发生禁止行为。

单凭最终哈希不能证明从未写入；“全程未覆盖”需要动作中介或完整写入事件记录。不要用一个看似通过的最终检查替代更强性质的证明。

**稳定成果：** 明确的条件性性质、假设清单、可执行测试及失效反例。测试无法证明开放环境中的所有执行都满足性质。

## 7. 方法提升路线：保持为高价值实验目标

### 7.1 在线先导

继续采用 40 个任务 × 4 组 × 2 次 = 320 次运行：

| 组别 | 设置 |
| --- | --- |
| A | 普通 Agent，同等预算内允许一般自检 |
| B | 关键步骤重申原始要求 |
| C | 结构化误差分析与证据反馈 |
| D | C 加候选修复保持条件与接受前复检 |

所有解析、检查和修复成本计入各自预算。未完成、超时、预算耗尽和环境故障按预先规则记录；不能事后选择性移除不利运行。

这四组用于分析与复检机制。若要声称评分有贡献，应先完成第 5 节的固定候选集比较，正式在线实验再增加“相同候选、不同排序规则”的消融，不能从 C 与 D 的差异推断评分价值。

### 7.2 正式验证

先导 40 个任务可用于调试、方法选择与方差估计；一旦用于选择方法，就不能再作为独立确认性测试。正式测试应使用新任务，并按模板或任务族防止改写泄漏。

主要比较为 D 与预先确定的强基线，主指标为“任务完成且全程无硬约束违反的运行比例”。若根据开发结果选择基线，选择规则须在独立测试前冻结；次要比较和探索性分析单独标记。

正式样本量依据先导的任务相关性、配对结果和最小实用效应确定。建议把提升 5 个百分点作为待讨论的实用目标，而非承诺结果；320 次探索运行不保证具有检测该效应的能力。

## 8. 把负向或不确定结果转化为可靠结论

### 8.1 不显著不等于没有作用

独立测试中效果差异的区间可能出现三种情况：

- 支持预先定义的实用提升：报告收益及成本与适用范围。
- 区间足够窄，排除了预先定义的实用提升：可报告当前设置下未达到目标收益。
- 区间宽，同时允许有用提升和无效或有害结果：结论是证据不足，不能宣称等效或无效。

如果希望声称两方法在实用上等效，应预先定义双向等效界限并采用适当分析。不能用普通显著性检验未拒绝零差异代替等效证据。

### 8.2 瓶颈替换诊断

| 干预结果 | 可支持的解释 | 不能直接推出的结论 |
| --- | --- | --- |
| 人工正确要求明显改善 | 规格解析是当前瓶颈之一 | 解析是所有任务的唯一瓶颈 |
| 标准正确反馈仍修不好 | 修复或执行能力受限 | 所有反馈方法都无效 |
| 离线评分准确、在线无收益 | 成本、调度或交互可能抵消收益 | 单凭该现象确定具体原因 |
| 复检减少退化但增加停滞 | 出现收益与完成率的权衡 | 只看违规减少就宣称整体成功 |
| 简单提醒与复杂系统表现接近 | 当前任务下复杂度的必要性未获支持 | 两者在所有场景等效 |

每项解释都要联系具体干预与区间结果。诊断中的标准答案条件应计入诊断成本并明确标注，不包装为实际可部署系统性能。

## 9. 最低可交付成果包与验收

以下是资源、工具和人工核验到位时的计划目标，不是已经完成的资产。

| 编号 | 交付物 | 最低验收条件 | 是否要求方法超过基线 |
| --- | --- | --- | --- |
| P1 | 40 项先导任务及逐项真值 | 合法路径、约束边界与重置方式均可核验 | 否 |
| P2 | 独立验证器与重放工具 | 接受合法变体、拒绝已知违规；固定轨迹可重复 | 否 |
| P3 | 受控轨迹与证据视图 | 目标 160 条轨迹、最多 320 视图；实际执行与来源可查 | 否 |
| P4 | 分析器和评分有效性报告 | 完整指标、配对分析、成本与失败案例 | 否 |
| P5 | 条件性保持分析及反例 | 假设、接受规则、验证边界与失效用例明确 | 否 |
| P6 | 在线先导报告 | 完整 320 次计划运行或解释未完成项，保留失败记录 | 否 |
| P7 | 独立确认性结果 | 冻结协议、新任务、样本量与不确定性报告 | 否，但需要更多资源 |
| P8 | 方法收益与泛化结论 | 同预算、强基线、跨设置复验及必要消融 | 是，属于争取目标 |

复现包建议包含任务与代码版本、模型标识和配置、随机设置、运行清单、原始工具记录、逐项判断、汇总脚本和环境说明。模型服务更新可能改变未来运行结果，因此区分“原轨迹可重算”和“重新调用模型可近似复现”。

没有模型调用预算时，仍可完成 P1、P2、P3 和 P5 的受控环境部分；不能宣称已经测得模型表现。没有独立核验资源时，应先交付未完成核验的草案，不能降低质量门槛后仍声称同等成果。

## 10. 分阶段投入与继续标准

| 阶段 | 优先投入 | 继续或调整依据 |
| --- | --- | --- |
| S0 | 先做 6 个任务，每个操作族一个 | 验证器与合法参考是否可信；失败则先修任务资产 |
| S1 | 扩展到 40 个任务和受控轨迹 | 能否稳定重放、是否覆盖关键错误；过易则在开发阶段调整 |
| S2 | 离线分析与评分诊断 | 分析器定位是否准确、评分是否有真实排序价值 |
| S3 | 320 次在线先导 | 是否存在可修复错误、退化与成本；据此选择正式主张 |
| S4 | 冻结方案，开展独立测试 | 判断实用收益、等效或证据不足，不事后改主指标 |

建议初期工作量以测量资产和诊断为主，暂不同时开发强化学习、多个检查 Agent 和复杂自适应调度。这是投入优先级，不是对完成工期或收益的保证。

停止增加系统复杂度的信号包括：标准反馈仍无法驱动修复、模型几乎没有可修复错误、内部评分与真实排序无关，或复检成本长期超过收益。届时优先完善诊断报告，并缩小或调整方法主张。

## 11. 对此前成功率估计的修订说明

此前“原型约 85%–95%、同预算超过简单基线约 40%–60%”属于基于有限信息的主观判断，未经过经验校准。它们不是统计置信区间，不是任务成功率，也不宜作为资源承诺依据。

本报告不通过增加任务包和诊断实验来人为提高这些概率。补充方案提高的是**交付路径的可控性**：当方法没有正向收益时，仍能交付高质量测量资产及有边界的结论。

在模型、预算、人员和验证质量明确之前，不再给出更精确的成功概率。完成 S0 和 S2 后，应依据实际数据重新评估风险，而不是继续沿用主观百分比。

## 12. 最终建议

将项目设置为“测量与诊断主线＋方法改进主线”。先保证任务定义、证据和评价可信，再验证误差分析与评分是否能改善决策。

最低成果目标为：一套可复现的小型任务与轨迹资产、一套独立验证工具、一份错误与修复退化的诊断报告，以及一个边界明确的约束保持说明。方法提升和跨模型泛化作为后续争取目标。

这样可以降低“方法没有提升就没有成果”的风险，同时保留研究诚实性：没有足够证据时，报告不确定；没有新颖性时，不把工程资产包装成突破。
