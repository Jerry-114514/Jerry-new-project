# M2b：来源/模板初筛及正式语义审查绑定

2026-10-23，development 范围。只使用两批已经公开的开发/训练案例，不含正式 test/OOD。真实标注和来源审查均为 0。

32 个视图对应 20 份公开任务合同；新三个领域变体仍保守归于一个操作来源簇。两批共有 12 个声明的来源 ID，但这不是已核验独立样本数。初筛标出 **12 对跨 train/validation 的同操作风险**，都仅由 shared_coded_operation_risk_only 触发，不能直接认定语义重复或正式泄漏。

本轮未扫描旧 40 个 fixture 的全部派生资产、所有外部数据或预训练来源。审核者仍须审查完整历史资产与未标记来源，不能用 12 对清单代替语义审核。

## 交付与复核

`inputs/` 为实际两份输入；`triage/` 包含合同、候选对、协调人案例、空白逐对表及结构化审查空模板。每个来源组的理由与出处为空，12 对决定均为空，所有实际审核声明为 false；它们不进入逐要求状态标注包。

```bash
python examples/results/formal-m2b-source-triage/audit.py
```

复核从输入重建全部文件并逐字节比较，确认空白模板被正式语义验证器拒绝。输出 `semantic_dedup_review_complete=false`，不自动批准。

AutoDL 最终 **182 项测试全部通过**；本地 172 项通过、10 项缺少 ML 依赖跳过。106 个源码/配置文件与远程匹配。九项新增测试覆盖观察去重与重复批次、跨划分同操作提示、排序与 case_id 冲突、公开 holdout 拒绝/私有风险、空白/过期/缺理由审查、缺失或未解决候选对及完全相同合同不能覆盖为独立、训练摘要不重读已删除协调材料，以及正式 readiness 拒绝文件存在但无人审查的内容。

`tests-core-initial-failure.log` 保留最初目标测试失败：Windows 测试夹具误用默认文本解码，导致含 Unicode 的案例哈希不同，验证器正确拒绝过期哈希，而测试预期到达人审声明检查。测试读取改为明确 UTF-8 后通过。初次全套 181 项记录在 `tests-autodl-initial.log`；增加逐对决定覆盖检查后，最终 182 项重新通过。无真实来源批准或正式训练被这些测试替代。

## 正式约束

正式语义证据从“文件存在”升级为 JSON 内容校验：绑定当前案例和重算初筛、全部来源组、逐对决定、理由、原始出处与先前公开资产审核声明。相同合同必须先合组/排除；未知和未解决对不能通过。模板只提供待填字段，不制造真实审核者。

冻结记录案例文件与审查文件 SHA 及验证摘要；training 阶段只检查摘要，all 阶段才重读协调人材料。工程协议保留兼容行为，不把旧工程证明变成正式批准。具体流程见[审查指南](../../../docs/source-template-review-guide.md)。正式 M2–M8 仍未完成。
