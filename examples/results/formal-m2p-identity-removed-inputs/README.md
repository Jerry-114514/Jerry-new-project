# M2补充：移除生成行身份后的公开输入复用检查

2026-10-25。本检查补强[M2o精确匹配](../formal-m2o-prior-public-inputs/README.md)中“随机行ID不同即可导致不匹配”的限制，不更改冻结数据、模型、提示、划分或推断方案，也不读取当前gold或模型预测。M5仍在运行，M2不勾选完成。

在三种既有模式之外，增加三种输入指纹：只删除字段名为rid、值为字符串且完整符合`[0-9a-f]{12}-[0-9]+-[0-9]+`的字段；分别保留路径、移除路径但保留文件组、再移除文件边界。其余字段、值、JSON类型和行顺序全部保留。该操作只是有界复用风险探针，不宣称该字段在所有任务语义中均可忽略，也不声称实现了字段别名或语义等价判断。

[实测摘要](summary.json)仍绑定1050份冻结公开源合同及原内容digest。当前输入共删除5134个符合格式的rid字段；提取到的历史输入中该格式字段为0，因此本次允许“当前输入多加一个生成rid”与旧输入相比较。并不把旧输入中的id、普通rid字符串或数字字段一起删除。

同一冻结提交的可达历史、两个目录根及962个JSON/JSONL内容对象，仍仅23个对象提取到支持格式的输入、共829次容器提取；937个对象未识别输入，2个无法解析。六种模式均未检出当前输入的精确复用。原历史对象清单和私有配对表留在本机，摘要记录SHA；零命中不能外推到未识别格式、外部资产、预训练数据、改名字段、改行序或近似内容，也不消除既有test/train近邻与独立性限制。

另作实际历史扫描的[阳性对照](positive-control.json)：仅取已公开`data/tasks.json`第一条的inputs，给每行新增上述格式的rid，不读取其oracle。原三种模式均不命中，新增三种均成功命中该工程源，共9条历史对象配对记录。记录次数不是独立源数量，不是正式模型或数据质量结果。三项单元检查另覆盖生成身份变化、路径差异、普通值/类型/顺序保留、prompt递归及排除答案字段。
