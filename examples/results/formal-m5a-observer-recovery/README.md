# M5本机备份观察器停滞与恢复

2026-10-25。此次事故涉及本机的SSH监测及封存后备份观察器。恢复前后，AutoDL上的M5生成进程身份、启动标识和协议绑定一致，预测计数持续增加；没有重跑生成、删除claim、揭晓标签或修改冻结源码。此回执不计模型效果、M5完成或M8完成。

## 实际观察与影响

旧观察器的本机进程仍存在，但最后成功状态停留在北京时间14:33:03，约五小时没有刷新。另发现14:34开始的遗留SSH，其直接Python父进程已不存在；旧观察器有等待中的线程。此前只核实进程存在的检查不足以证明监测有效，后续需同时核对最近成功刷新时间及实际生成进程。

旧代码以带PIPE捕获和180秒超时的Python包装器调用另一个Python包装器，再由后者启动SSH。超时清理直接包装器后，遗留SSH仍可持有输出管道，导致清理等待不返回；观察到的进程关系与该机制一致。没有取得原Python阻塞栈，最初SSH停滞由何触发仍未确定，不将这一推断写成已证明的网络根因。

发现事故时，M5仍在预测阶段，尚未获得全部条件封存。因此预测归档尚未开始，不能把“观察器已启动”当作跨主机预测备份已经完成。六个正式模型的跨主机备份是此前单独完成的工作，本次不宣称重新逐字节核验全部模型。

## 恢复措施和验证

- 核对命令行及进程关系后，仅终止旧本机观察器和属于该观察链路的遗留SSH；旧目录和日志保留。
- 观察器直接启动SSH/SCP，设置连接超时及有限保活；输出使用临时文件，超时清理其本机子进程树。
- 观测错误保留为`observation_unavailable`，仅重试读取状态；不以旧快照冒充新观察，也不重试模型生成。
- 恢复使用原有密钥及known_hosts记录。首次新绝对known_hosts路径的真实连接预检曾失败，恢复原相对路径后通过；没有关闭主机校验或改变服务器认证。
- 新观察器使用新目录，保留固定协议、模型绑定和生成进程身份检查；只有全部条件封存且通过校验后，才创建预测归档、跨主机复制并核对成员哈希。

本机合成子进程检查覆盖正常返回、非零错误保留及带后代进程的超时：约1.705秒返回，确认所创建的后代进程终止。此检查不使用GPU、测试标签或模型输出；不等于真实断网、系统睡眠及所有SCP失败路径均经实测。

真实只读连接预检通过后，观察器于北京时间19:52:06取得当前状态；19:54:07的后续自动轮询再次更新，源进程标识匹配，计数为A/B/C及余弦seed 0各1240、余弦seed 1为972。这是带时间的恢复检查点，不是最终预测总量或准确率。
