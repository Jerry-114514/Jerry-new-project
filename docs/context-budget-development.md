# 新训练候选的上下文与 5090 压力检查

2026-10-23，开发证据，未完成正式长度/计算预算审核。原始记录和可复核代码见 [M3a 目录](../examples/results/formal-m3a-context-probe/README.md)。

## 已测范围

使用官方原始 Qwen3.5-9B 的 tokenizer，按实际 `formal_prompt` 与非 thinking chat 前缀，对新训练候选的 24 个视图分词。零样本提示长度为 **727–1,420 tokens**。在草案 context_limit=2048、max_new_tokens=512、token_budget=8192 下，24/24 均能完整预留 512 个生成 tokens，不需要截断。

此处只测零样本输入，没有真实人工审核的少样本答案或监督目标。因此不能据此声称 B 条件、训练样本或长历史已覆盖；强基线示例和审核后的完整目标仍须重新核验。训练器对超长样本报错，不会静默截掉证据或标签。

另用无关的合成目标 `{"hardware_probe":"synthetic-no-task-label"}` 检查内存形状。它不表示任何任务状态，不是自动生成的诊断监督。构造实际完整序列长度恰好 1024/2048 的 train/validation 数据，每例目标 11 tokens；test 文件故意写成非法 JSON，运行必须开启 defer-test。

在 RTX 5090 上分别进行两次更新，均使用 4bit NF4 QLoRA、BF16、rank16/alpha32、微批次1、累积2、余弦、种子0、每步验证与检查点。两档均完成四个样本暴露，梯度/损失有限，未读取 test。

| 实际完整序列 | allocated 峰值 | reserved 峰值 | 两更新训练循环 | 整个进程调用墙钟 |
| --- | ---: | ---: | ---: | ---: |
| 1,024 tokens | 16.82 GiB | 17.51 GiB | 5.30 秒 | 35.21 秒 |
| 2,048 tokens | 20.18 GiB | 24.13 GiB | 7.38 秒 | 36.99 秒 |

allocated 已包含在 reserved 中，两者不能相加。这些是训练器在准备模型后重置统计所记录的 PyTorch 峰值，不是模型加载全过程、非 PyTorch CUDA 分配或主机 RAM 峰值。短循环时间包含验证、检查点等实现开销，但不包含所有加载/最终导出；全调用墙钟另列。只有两更新，不能作为稳定吞吐或六次正式训练总时长。

## 可以作出的决定

当前 **2048 可继续作为待审的开发起点**：实际新零样本提示可预留输出，独立的相同长度合成压力负载也能运行。但尚不能保证所有真实目标、少样本上下文、更多轮历史及恢复阶段都能运行。未测 4096，不把 2048 结果外推到 4096。

合成目标的损失下降或最佳检查点没有研究质量意义；所产生的适配器不能作为 D/E 正式端点，也不作为完成长期模型备份的证据。正式预算的审核状态仍为 false。

## 冻结前必须补充

1. 对审核后的 train/validation 全部真实 prompt+completion 测量长度分布，记录极端值和明确的超长处理，不接触测试标签进行调参。
2. 对实际选定、已审核的 B 条件少样本和闭环长历史重新计算全部调用预算；保持对照条件预算规则一致，保留拒绝或耗尽记录。
3. 用实际监督目标在典型和最大长度进行更长的开发短跑及恢复，测量稳定更新耗时、加载/保存/评估、PyTorch 与主机内存；验证验证频率和检查点成本。
4. 按冻结的更新数、六组计算量、诊断及闭环调用量计算总预算，保留不确定性，完成具名资源审核。不能以本开发报告替代审核者签字。

本轮不改变 idea.md 的正式数据、人工标注、功效与六次训练要求，也不将正式准备状态改为 ready=true。
