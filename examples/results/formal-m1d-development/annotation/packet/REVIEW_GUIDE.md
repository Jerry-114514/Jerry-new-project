# 独立审核说明

本包是 8 个公开开发源任务的真实模型执行观察，尚无人工作过审核。两位审核者分别独立填写 `review-template.jsonl`，提交前不交换判断，也不查看仓库中的模型分析、评估指标或来源映射。

`cases.jsonl` 只有公开任务和实际观察。`execution_spec` 是公开规格，不是参考答案；`observation.files` 和可见事件来自虚拟工具环境。模型写出的报告/自报完成不能替代其他证据。按每个要求的原文及规格逐项标记：

| 状态 | 使用条件 |
| --- | --- |
| satisfied | 当前可见证据足以证明要求满足 |
| violated | 当前可见证据足以证明要求未满足或已被违反 |
| unknown | 所需证据未提供，不能证明满足或违反 |

本包的视图取自已结束的执行提议或候选检查点。必需交付物缺失不是满足；输出尚未生成时，不能仅根据输入能够正确处理就判结果已完成。报告缺失与真实历史不可见应分别判断。

具体核验要点：输入文件即使后来恢复，写入/删除历史仍违反保护；字段检查看工具实际 `ok`，而非 `claimed_ok`；结果要核对操作、目标路径、全部记录、边界条件和类型；报告要核对实际输出行数。数据结果错误但报告如实统计实际文件时，两项要求可有不同状态。

证据引用使用：

- `request`：公开请求。
- `input:<路径>`：原始输入，例如 `input:input/data.json`。
- `file:<路径>`：观察中确实存在的当前文件。
- `snapshot_paths`：观察文件路径的清单，可与 request 一起支持必需文件缺失。
- `event:<索引>`：可见工具事件。历史为 null 时不得引用事件。

不要自行创造 `observation:files:...` 等引用。已知判断需要非空证据；unknown 可为空。状态和证据分歧均交由第三位独立人员仲裁。只在实际完成审核后填写稳定的 reviewer 标识和 `human_verified=true`，不得把自动标签登记为人工核验。

这些视图只有 8 个源任务，重复运行和去重前的数量不增加独立样本数。它们不能被重新包装成正式测试集。
