# 自然轨迹完成后的全量开发验证成本测量

2026-10-23。前次两更新只验证了两个训练及两个验证样本，不能用51.7秒直接线性推算六组正式训练总成本。本轮已启动CPU依赖等待任务，待M3j的评分、32源自然采集及程序标注全部完成，再做完整长度与验证成本测量。发布时仅等待，没有资源结果或正式训练启动。

输入限定为原2400训练、600验证SFT及自然轨迹的32训练、32验证视图，预计2432/632视图。自然视图继承原source/split，完整来源数仍为600/150；不增加为616/166。核对原数据哈希、自然导出清单、跨集合来源及case ID。只读train/validation，不读test/OOD/gold库。自然前驱失败、数量不完整或输入变动时不启动训练。

逐条使用生产encode_pair和固定官方tokenizer，保留完整证据与监督目标EOS。记录总长、监督token、分位数及全体token量。训练压力样本按实际总长取下中位数和最大值，同长按case_id排序，不按loss挑选。验证使用全部预计632视图。上下文为完整开发数据最大总长向上取1024整倍数；若超过本轮预设16384上限，保留长度证据并停止，不截断或删题。该上限不是显存可行保证，OOM也不自动重试。

压力短跑使用官方原始9B、NF4/BF16、rank16/alpha32、微批次1/累积2、cosine、seed0、学习率5e-5/最低5e-6、四次更新。第2步评估完整验证并保存，退出后以相同配置恢复至第4步，再评估完整验证。原中间结果另存；核对输入/base绑定、历史前缀、累计监督量、完整验证目标分母及defer-test。数据目录放无效JSON test标记，若错误打开应失败。

新增轻量计时包装仅调用既有evaluate_loss一次，保持参数与返回对象，前后CUDA同步并记录每次完整验证墙钟、目标token及loss。它不改变损失计算、优化器、调度器或数据，不用两个压力样本的效果声称模型质量改善。原训练源码不修改；包装源码绑定哈希。完成后保留两次进程墙钟、完整验证耗时、显存和恢复记录，用于估算验证频率与总预算。训练样本只有两个长度压力案例，其吞吐不能当作完整训练分布的无偏估计。

此短跑不计六组正式训练，也不证明连续训练与恢复数值完全一致。原微型恢复检查和本实际恢复可行性证据分开解释。压力适配器不是正式分析器端点。源码仍固定干净b4a757a，所有等待/采集/本压力测量都终止前不更新AutoDL规范检出；新代码继续单独上传GitHub。
